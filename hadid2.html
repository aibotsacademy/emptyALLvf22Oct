    How HADID Charter works with Avinode

    The client searches and requests. The broker sources, quotes and books inside Avinode. HADID Charter carries the client from request to signed agreement and payment.

      Broker profile

      Shown to clients on the site, offers, the charter agreement and payment instructions.

      Pricing

      Applied to every estimate and offer. Hourly rates are the operator's wholesale rate per block hour, in USD.

      Default markup on the operator's price. You can change it per offer.
      Balance due 7 days before departure. Trips within 14 days pay 100%.

      Avinode connection

      The Avinode API token and the OAuth client secret are set on the HADID backend as environment variables. They never reach this page, which is what Avinode's go-live rules require. This page only needs the backend address.

      Set on the backend (AVINODE_ENV); shown here for reference.
      Protects the broker routes on the backend. Not an Avinode credential.

      Automation

      Every request becomes a client lead and RFQs automatically (POST /leads, POST /rfqs). These rules decide when the client gets an offer. In live mode the backend applies its own copy of them (AUTO_OFFER, MAX_OFFERS, OFFER_AFTER_MINUTES, MARKUP_PCT).

      Register one webhook in Avinode (POST /webhooks/settings) pointing to {backend}/webhooks/avinode?k={WEBHOOK_KEY} with the event types ClientLeads, TripRequestMine, TripRequestSellerResponse and TripChatFromSeller. Card payments: point your payment provider's webhook at {backend}/payments/stripe.

      Aviapages connection

      Empty legs and charter availability from the Aviapages API v3. The search reads GET /v3/empty_legs/; before a client request is sent, the desk re-checks the leg with GET /v3/empty_legs/{id}/.

      Backend mode uses AVIAPAGES_TOKEN on the server, so the token never reaches visitors.
      Sent as Authorization: Token <key>. Match what the Swagger “Authorize” box shows.
      Follows the list's next link up to this many pages.

      Filters sent with GET /v3/empty_legs/

      Copy the query parameter names from the Swagger page. Leave a box empty to skip that filter; HADID Charter filters the results again by route, date and passengers either way.

      Field mapping

      Where HADID Charter finds each value in an empty-leg record. List the candidate fields in order, separated by commas; a dot goes into a nested object (for example aircraft.aircraft_type). Airports may be ICAO strings or objects with an icao field.

      Endpoints

      EndpointPurposeUsed by HADID Charter
      GET /v3/empty_legs/List empty legs and availabilitiesClient search
      GET /v3/empty_legs/{id}/One recordRe-check before a request
      POST /v3/empty_legs/Create a recordBackend, desk key
      PUT /v3/empty_legs/{id}/Replace a recordBackend, desk key
      PATCH /v3/empty_legs/{id}/Update part of a recordBackend, desk key
      DELETE /v3/empty_legs/{id}/Remove a recordBackend, desk key

      Create, replace, update and delete are for publishing your own or your operators' empty legs; they are open only to the broker routes on the backend and are not used by the client page.

      Other sources

      Marketplaces and operator feeds besides Avinode and Aviapages. Switch a source to live and add its credentials.

      These credentials stay in this browser. Use live mode on the broker's own work devices only. Before going public, move these sources behind the backend too, the same way as Avinode.
      The provider URL is appended to this prefix, URL-encoded when the prefix ends in “=”.

      Payments

      Clients pay by bank transfer or by card through your payment provider's hosted checkout. This page never asks for card numbers.

      Opens in a new tab with the booking reference and client email added. Leave empty to simulate card payments.

      Backup

      Copy the configuration to move it to another device. The desk key and other-source credentials are included, so keep the copy private.
